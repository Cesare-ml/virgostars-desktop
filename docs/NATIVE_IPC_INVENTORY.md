# Native IPC inventory — offline, fail-closed source audit

**Status:** local developer verification only (13 November 2026). This is not a native security audit, penetration test or a proof that a released Windows application is safe.

## Why this gate exists

VirgoStars Desktop's synthetic prototype has exactly two intentionally local Tauri commands: `desktop_runtime_info` (read-only capability probe) and `search_offline_places` (read-only SQLite/FTS5 place search). A change to Rust's command registry, the TypeScript transport contracts or Tauri privileges must not be mistaken for a harmless UI refactor.

Run `npm run verify:ipc` or `node scripts/verify-native-ipc.mjs` from the repository root. The script requires no installed npm dependencies, Rust compiler, catalog database, network access, user profile, account login or private data. It exits nonzero on unexpected registry/adapter/capability changes. Its CLI deliberately prints only a generic failure, not source text or personal paths.

## Exactly what is checked

- The Rust Tauri builder has exactly one explicit `generate_handler![...]` registration with two **fully qualified** reviewed handlers (`runtime_probe::desktop_runtime_info`, `offline_places::search_offline_places`), not just matching unqualified function names. Renaming a handler module fails closed.
- All `.rs` files under `src-tauri/src/` are recursively inspected for `#[tauri::command]` declarations and Tauri plugin initialization/registration patterns (`.plugin(`, `.plugins(`, `tauri_plugin_…`). The builder entrypoint is scanned as well. The two reviewed Rust modules must exist; additional command declarations, plugin references, unsupported attribute forms, or duplicate filenames with ambiguous module identity fail closed.
- The two matching TypeScript protocols use the known literal command names and contain **exactly one** direct native `.invoke(...)` call each. A second call (including bracket-notation `['invoke'](...)`) requires explicit review even if the approved call is still present.
- Recursively inspect frontend files under `src/` (including `src/main.ts` and nested `.ts`, `.tsx`, `.js`, `.mjs` files) for *any literal* `@tauri-apps/` package reference, including dynamic imports. The only reviewed transport adapters are `runtime.ts` and `offline-places.ts`; each must import **only** named `invoke` and `isTauri` from `@tauri-apps/api/core`, without aliases, and issue one `invoke<unknown>(command, …)` call. Additional native imports, direct calls or plugin references require review.
- Tauri `app.security.capabilities` is still the empty list, and `app.withGlobalTauri` is not enabled. **Important:** Tauri 2 treats an empty (or omitted) capabilities list as **automatic discovery** of capability files in `src-tauri/capabilities/`; an empty list is **not**, by itself, proof of no permissions. Therefore the audit also requires this directory to be absent or genuinely empty. Any new file, nested directory, or symlink at that path triggers an explicit security review.
- `src-tauri/build.rs` must retain the reviewed minimal `tauri_build::build()` invocation. Changing the build script may change command manifests or capability discovery and requires a separate review.
- New command names, additional direct Tauri imports, added capability files, modified native build scripts and expanded capabilities **fail closed**. If these changes are later approved, update the allowlist, tests, documentation and threat model in the same reviewed PR.

## Limitations and acceptance

This is a narrow **source-level regression gate**, not a full Rust/TypeScript parser. Tauri's documented automatic capability discovery is the reason for the additional `src-tauri/capabilities` directory check (see https://v2.tauri.app/reference/config/). The scan intentionally treats any matching package string in a supported frontend source file (even in a comment) as reviewable; it can produce false positives. Similarly, the conservative Rust attribute scan may require an allowlist update after a legitimate macro-format change. It cannot detect string-building tricks, indirect/aliased native calls, unusual module aliases, other file extensions or HTML scripts, runtime-generated plugins, frontend XSS, misconfigured production permissions, unauthorized native plug-ins or malicious code in dependencies. Do not cite a green audit as proof of complete IPC confinement.

Verification to date: **21 synthetic Node source/checkout tests** in `tests/native-ipc-registry.test.mjs` passed in an isolated Node.js 22.16.0 local mirror; the audited script and tests have byte-identical GitHub blobs (`8a602eb4d98e602f25422d5e1e9b21b5b640d36a` and `d0fa04ab7a59820d1ac2286de33836f51539c08c` respectively). `node --check` also passed for both files. The complete project `npm test` / `npm run check` has **not** been run. Run `npm test`, `npm run verify:ipc`, `npm run build:ui`, `cargo test` and inspect the compiled Tauri permissions and WebView2 behavior on an authorized Windows checkout before approving security-sensitive native changes. Any future Rust ephemeris, device-authentication, secure storage or sync command needs its own contract, privacy and authorization review; never silently extend these demo commands.

The audit contains no astronomical computation, user birth records, credentials, network requests, DB migrations, releases, GitHub Actions, production changes or dependency additions. It does not modify Tauri permissions.

## Standalone Tauri build entrypoints (2026-11-13)

The ordinary npm commands `tauri:build` (synthetic assets) and `tauri:build:private` (separately authorized artwork) now **first** run `npm run verify:ipc`, then build and verify their Angular frontend, generate the local development icon and invoke `tauri build`. This closes a source-configuration audit gap in those two convenience commands; a direct native build no longer starts through them if the reviewed Rust command registry, frontend Tauri adapters or capability files have unexpectedly changed. `tests/standalone-tauri-build-ipc-gate.test.mjs` guards the ordering and enforces consistency with the existing city builds.

The optional city-enabled Windows npm commands already audit native IPC and their resource-only override; those commands are unchanged. The **PowerShell/CMD Windows acceptance bootstrap** also continues to run `verify:ipc` explicitly before packaging the **already audited** Angular output with the Tauri CLI directly. It must not be replaced with `npm run tauri:build` because that rebuilds Angular after the independent verification. Manual `tauri build` or `npm exec -- tauri build` outside the npm build commands can still bypass this source audit.

This is a **read-only static gate**, not proof of compiled capabilities, runtime access control, network isolation, dependency integrity, signing or public release readiness. Full `npm test`, Rust `cargo test --locked`, actual Windows Tauri compilation and WebView2 smoke still require an authorized local checkout. No accounts, production services, city catalog assets or releases are accessed by this change.
