# Manual Horizons vector acquisition — review-only

**Status:** Node.js 22+ acquisition prototype, locally tested with mocked HTTP responses. No live NASA/JPL response was retrieved in the development environment; no scientific numerical accuracy or independent source authenticity is established.

This tool adds an explicit, operator-initiated acquisition step to the independent query-plan generator in [HORIZONS_INDEPENDENT_VECTOR_PLAN.md](HORIZONS_INDEPENDENT_VECTOR_PLAN.md). It never runs in the Desktop app, never accesses user accounts, and never enables chart-ready astronomical results.

## Commands (from a full repository checkout)

```powershell
node scripts/ephemeris/prepare-horizons-vector-plan.mjs --tdb-jd 2460000.500000 --out 'D:\review\horizons-plan.json'
node scripts/ephemeris/acquire-horizons-vectors.mjs --plan 'D:\review\horizons-plan.json' --output-dir 'D:\review\responses-new'
```

The TDB Julian day above is **illustrative**. Use an epoch independently reviewed against the requested timescale. Neither this script nor the plan generator converts UTC to TDB. The output directory **must not already exist**. It is created exclusively (permissions restricted where supported) and all ten original text responses plus `response-manifest.json` are written there. A failed acquisition removes only the newly created output directory, and never overwrites an existing directory or file.

Acquisition is **opt-in** and network access is required on the operator's computer. The script performs up to ten sequential HTTPS GETs to the exact allowlisted `https://ssd.jpl.nasa.gov/api/horizons.api` query URLs generated by the existing plan module, with 2.5 seconds between calls, 15-second request/body timeout and a 512 KiB response limit. HTTP redirects are disallowed. No API key, custom server endpoint or proxy credential is accepted from the plan. It refuses any plan that differs, even by a single field, from `buildHorizonsVectorPlan` output. Invalid plans are rejected **before** any network activity.

## Accepted response format

For each requested NAIF target, the raw text must include matching Horizons-style header values:

- Target NAIF ID; center `Solar System Barycenter (0)` and `BODY CENTER`
- Output units `KM-S`, output type `GEOMETRIC cartesian states`
- Output format `2 (position and velocity)`
- Reference frame `ICRF` or `ICRF/J2000.0` **and** coordinate system `Earth Mean Equator and Equinox of Reference Epoch` (so the ecliptic-of-J2000 output is refused)
- Start time labeled `TDB` and an unambiguous `JDTDB` column
- Exactly one row between `$$SOE` and `$$EOE`, containing the requested TDB Julian day, calendar stamp, three position components in kilometres and three velocity components in kilometres per second

The parser requires finite numeric values, rejects missing or duplicated rows, wrong target, origin, frame, units, format, and mismatched epoch. The original bytes are saved without reformatting; coordinates are never printed in CLI output. The manifest records for each target its source **claim** (if stated), original-response SHA-256 and exact query-URL SHA-256, as well as the unverified common plan epoch.

**Important:** a text file with internally consistent headers could be fabricated. `STRUCTURE_CHECKED_NOT_AUTHENTICATED` means precisely *structural and byte-integrity checks only*, never NASA/JPL cryptographic provenance or scientific accuracy. A source claim of `DE441` or `DE440` is copied as an untrusted label, not treated as a kernel audit. The raw state vectors are **solar-system-barycentric ICRF Cartesian**, and cannot be directly compared to Desktop's topocentric mean-of-date ecliptic positions. The independent scientific normalization and actual Rust parity remain separate review gates.

If the live JPL response differs from the strictly supported header layout, capture the error context privately and revise the parser **with reviewed genuine samples and regression tests**. Do not remove frame, center or time checks just to accept unrecognized output.

## Security limitations

Request bodies are bounded and malformed/oversized HTTP responses are rejected; connection retries, 30x redirects and partial-download resumptions are deliberately **not** supported. A run interrupted while writing may leave a partial directory until normal error handling resumes; remove it only after manual inspection. Directory/file metadata checks are best effort on the local OS. Hostile concurrent filesystem replacement, authorized proxies, TLS interception, server-side dataset changes and cross-platform filesystem semantics have not been independently audited. Output paths must be in a trusted, private local folder.

```text

node --test tests/acquire-horizons-vectors.test.mjs

```

Tests use local temporary files, simulated `Response` objects and a fake HTTP transport. They exercise all ten canonical URLs, structure/metadata checking, source hashes, no-overwrite, rollback, wrong target/frame/units/epoch, malformed vector tables, oversized HTTP responses and sanitized CLI errors. The plan module used in local tests exactly matches the upstream Git blob `c14b444655fdaf6ce8a7d4e561fa5c6b98ed4ee8`.

**Not executed:** live Horizons queries (network unavailable), authentic response validation, independent normalizer, real classic DE441 kernel, Rust/Cargo, full Desktop npm/Angular tests, Windows Tauri/WebView2 build. No releases, merges, GitHub Actions, production changes or publication.
