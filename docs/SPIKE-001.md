# Spike 001 — Tauri 2 + existing Angular/Three.js renderer

**Status:** first implementation draft (2026-11-10), **not a validated Windows build**. The packaging code passed eight synthetic Node.js tests locally; Rust/Tauri compilation and the actual WebView2 graphics test have **not** run in the authoring environment (no Rust toolchain or npm registry connection).

## What it does

A minimal Tauri 2 Rust shell hosts the **real Angular/Three.js Astrological Charts demo** built separately from the private `Cesare-ml/astrological-charts` repository. It does **not** copy the renderer's source code or any private VirgoStars artwork. The upstream demo renders synthetic planetary positions and generated checkerboard symbols, with natal/transit/synastry/latitude modes, zoom, skins and PNG export.

This spike checks desktop/WebView compatibility and offline bundling only. It is **not** the final large-chart workstation UI.

Before compiling, `scripts/generate-spike-icon.mjs` builds disposable PNG/ICO icons for Tauri without redistributing any original art. The icons are not final VirgoStars branding.\n\nThe packager `scripts/prepare-synthetic-frontend.mjs` stages `astrological-charts/dist/demo/browser` plus only the locally generated synthetic asset pack. Each asset is independently verified against SHA-256, path and byte-size metadata and the manifest's synthetic source marker. The script rejects traversal, symlinks, collisions, tampered image data and unexpected compiled file types. A separate tiny bootstrap script changes the upstream demo's asset base to the **same Tauri application origin**, avoiding an HTTP image server after packaging. It modifies only a new ignored staging directory; upstream files are unchanged.

## Windows 11 setup

**One-command guided build (PowerShell):** from `virgostars-desktop`, run `powershell -NoProfile -File .\\scripts\\build-windows-spike.ps1`. The script checks prerequisites, installs locked Charts dependencies, generates/reuses synthetic test assets, builds the demo, installs the pinned Tauri CLI, runs Node tests and attempts the Rust build. It changes only local development folders in the two checkouts and never accesses production.

Prerequisites: Node.js 22 LTS and npm, the current stable Rust MSVC toolchain, Microsoft C++ Build Tools and WebView2. Place both authorized private checkouts as sibling folders `astrological-charts` and `virgostars-desktop`. No production VirgoStars or private user account is required.

From `astrological-charts`, in PowerShell:

```powershell
npm ci
npm run demo:pack
npm run build:demo
```

The synthetic pack generator refuses to overwrite an existing `.local/demo-pack`. If a valid synthetic pack already exists, reuse it and skip `npm run demo:pack`. **Never substitute the private artwork pack.**

From `virgostars-desktop`:

```powershell
npm install
npm test
npm run tauri:build
```

`npm install` is required initially because the lockfile must be generated by a developer with real registry access; **commit and review that lockfile in a follow-up Windows validation PR**. The CLI dependency is pinned to `@tauri-apps/cli@2.12.2`, and a `Cargo.lock` must also be generated and reviewed after the first Rust build. The build expects `../astrological-charts` and creates `.local/frontend`. `bundle.active=false` deliberately builds only a **prototype executable**, not an MSI or NSIS installer. Locate the actual output under `src-tauri/target/release` and record it on Windows.

To repeat packaging, first inspect and manually remove **only** the generated `virgostars-desktop/.local/frontend` directory. The packager refuses to replace an existing directory.

## Live development option

With a pre-generated synthetic demo asset pack, run in two separate terminals from `astrological-charts`:

```powershell
npm run demo:assets  # localhost:4177, manifest-verified synthetic images
npm run demo         # localhost:4200, Angular renderer
```

Then in `virgostars-desktop`:

```powershell
npm run tauri:dev
```

Development requires those two **loopback-only** servers. The packaged application is designed to use only embedded assets.

## Explicitly not implemented

No real VirgoStars login/session, sync, SQLite/encryption, private user data, astronomical calculation engine, Python extension, signed updater, platform installer or official public release. Generated charts have **illustrative positions only**. No licensing/publication status changes.

The next vertical slice is an Angular UI owned by the desktop repo with the large central chart, importing the upstream library without vendoring. Then add a typed Rust bridge and verified astronomical integration. Never modify the web backend, other repositories or live accounts as a side effect.
