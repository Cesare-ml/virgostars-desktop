# Windows native GUI smoke — manual acceptance gate

**Status:** source-level Windows 11 x64 launcher for the experimental Tauri prototype. Does not constitute a release, production readiness, real astronomy, authentication, signing, or successful WebView2 visual acceptance.

## Why

Desktop doctor and post-build gates verify prerequisites, local CSS/JavaScript resources and PE32+ GUI headers. They cannot prove that a GUI process launches and creates a window. The first Windows smoke test observed an initially unstyled synthetic chart. Valid CSS files alone do not prove WebView2 applied those styles.

## Prerequisite

Build the authorized desktop and sibling Charts checkout following [Windows build gate](WINDOWS_BUILD_GATE.md). The new script does not build, repair files, install dependencies, modify execution policy or download anything. It runs on Windows only and uses the exact fixed-path executable:

    src-tauri/target/release/virgostars-desktop-spike.exe

## Fast process/window smoke

Run from the desktop repository root in PowerShell:

    powershell -NoProfile -File .\scripts\smoke-windows-native.ps1

This runs read-only checks, in order: Desktop versions; Tauri security settings; the native IPC command allowlist; the full synthetic offline bundle (HTML, local JavaScript, CSS, approved asset hashes); compiled global CSS; compiled component CSS; Windows PE header; and **native executable vs. Angular bundle timestamp freshness**. If any fails, no executable launches. When all checks pass, the script starts the fixed-path executable and looks for a nonzero main-window handle for up to 15 seconds, configurable between 2 and 30.

The new read-only `BUNDLE_FRESHNESS` preflight rejects a Tauri executable whose modification time predates a packaged Angular file by more than one second. It inspects `index.html`, the root JavaScript and CSS entrypoints, and all nested bundle files (including lazy chunks and synthetic assets); symlinks, missing entrypoints and malformed trees fail closed. The scan is bounded to 8,192 files, 1,024 directories and 16 directory levels. Each encountered file, scanned directory and the executable are checked for metadata changes during the traversal (device/inode, size and creation/change and modification timestamps); inconsistent snapshots fail closed. **All visited directories are checked a second time after the entire recursion**, so a directory changed after its subtree was traversed cannot pass solely because its local check already ran. These checks reduce the chance of accepting a bundle modified during inspection but cannot eliminate a final time-of-check/time-of-use race. After rebuilding Angular, **rebuild Tauri too** before retrying this smoke. File timestamps may be copied or manipulated, so passing this gate **does not prove** that the executable embeds those same bytes, was signed, or renders correctly in WebView2. The prior offline bundle and PE checks remain mandatory.

The launcher resolves `node.exe` once as a PowerShell **Application** command, rather than running an alias, function or `.ps1` wrapper named `node`. If no executable can be resolved, it fails with `NATIVE_SMOKE_NODE_REQUIRED` before any preflight or GUI launch. This pins the command selected from the local `PATH` for the duration of the smoke test; it does **not** independently authenticate or verify that Node installation.

The full-bundle check requires the synthetic staging manifest generated by the documented build. It does not download files or accept an arbitrary asset pack. The child-process preflight output is suppressed, including on failure, to avoid printing absolute checkout paths. Both a nonzero Node exit code **and a terminating PowerShell/native invocation or redirection error** produce the stable `NATIVE_SMOKE_PREFLIGHT_FAILED_<LABEL>` message, with no raw OS exception exposed. A failed gate always prevents native GUI startup. A contributor can rerun that specific read-only Node checker in a trusted local shell to investigate. A pass validates **current filesystem sources and artifacts**, not the bytes previously embedded in an older executable: rebuild the native binary after changing Angular artifacts. 

If the process exits before displaying its window, cannot be inspected, or fails to create a window within the configured deadline, the script attempts to stop **only the process handle created by that smoke run**, waits up to two seconds for cleanup, then returns a stable failure code. Cleanup errors are suppressed to avoid leaking local OS details. An instance that *does* open a window remains running for manual inspection; other already running instances are never searched or closed.

After detecting a nonzero main-window handle, the runner performs a **second check 250 ms later**. If the process exits, its window disappears, or the process becomes unreadable, startup fails with a stable label (`NATIVE_SMOKE_EARLY_EXIT`, `NATIVE_SMOKE_WINDOW_DISAPPEARED` or `NATIVE_SMOKE_PROCESS_UNAVAILABLE`) and follows the same scoped cleanup path. This detects some transient launch failures, but does not prove long-term stability or that WebView2 has painted the interface.

WINDOW_DETECTED means a main GUI window handle was observed. It does NOT confirm that WebView2 styled the app, that the chart renders, that offline works, that the process stays alive, or that the binary has a valid signature. The app remains open for inspection. No local path or raw OS exception is printed.

## Complete manual visual checklist

Stop the development server and disconnect Internet access. Then run:

    powershell -NoProfile -File .\scripts\smoke-windows-native.ps1 -Interactive

A human must affirm all eight checkpoints: visible CSS grid; **live CSS/geometry probe = active**; centered synthetic chart; light/dark themes; four chart modes and zoom/fit; synthetic PNG export; truthful offline city-search state; and operation without Internet/dev server.

For the new **layout** checkpoint, open **Settings → Layout diagnostics / Diagnostica layout** in the running desktop window and select **Recheck styles / Ricontrolla stili**. Confirm **Interface grid detected / Griglia dell’interfaccia rilevata**, which represents the runtime `active` state from `src/app/desktop-layout-probe.ts`. Answer **No** for missing CSS, hidden canvas, collapsed chart area or unavailable probe. The separate **styles** checkpoint still requires an actual visual inspection: even `active` only verifies sampled computed styles and geometry, **not** pixel-perfect WebView2 rendering.

Respond y/yes or s/si/sì for a confirmed success. Enter or any other response counts as failure. Any failure returns exit 1 and lists only fixed checklist identifiers. This is a manual observation, not instrumented screenshot, accessibility, GPU, CSP, performance or network-trace verification.

The script creates no reports, scans no birth data, captures no screenshots, invokes no network download, and never automatically closes the app.

## Verify source contract without Windows

    node --test tests/windows-native-gui-smoke.test.mjs
    node --test tests/verify-native-bundle-freshness.test.mjs

This verifies fixed executable paths, gated launch order, bounded process observation, explicitly manual acceptance, and absence of file-write/network tooling in the source. It is not a native or visual test.

## Troubleshooting

- NATIVE_SMOKE_NODE_REQUIRED: install a supported Node.js Windows executable or inspect `Get-Command node.exe -CommandType Application` in a trusted shell; PowerShell aliases or wrappers are not accepted.
- NATIVE_SMOKE_PREFLIGHT_FAILED_*: rerun the corresponding gate, never disable security/CSS checks as a workaround.
- NATIVE_SMOKE_PREFLIGHT_FAILED_BUNDLE_FRESHNESS: run `node scripts/verify-native-bundle-freshness.mjs` locally; if stale, rebuild the offline Angular bundle **and** the native Tauri executable using the documented locked build path. Do not bypass the gate.
- NATIVE_SMOKE_LAUNCH_FAILED: Windows could not start the compiled process.
- NATIVE_SMOKE_EARLY_EXIT: process exited before creating a main window.
- NATIVE_SMOKE_NO_MAIN_WINDOW: process stayed alive but exposed no main-window handle within the deadline.
- NATIVE_SMOKE_MANUAL_FAILED: at least one human acceptance checkpoint remains unconfirmed.

For CSS problems inspect the actual WebView2 console and ensure the newly compiled executable was launched. Do not relax Tauri CSP or introduce remote CSS fallbacks.

Scope: synthetic only; no production, cloud accounts, private catalogs, sensitive assets, signing keys, deployment, GitHub Actions, publishing or main merge.
