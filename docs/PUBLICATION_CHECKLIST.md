# Public visibility release gate

**Current status: BLOCKED — do not change this repository's GitHub visibility yet.**

This checklist is for a future, separately approved source-publication event. A source-license PR, even if merged, does not remove these blockers.

## Confirmed blocker: protected city database in a GitHub Release

- [ ] Move, remove or otherwise legally clear the `world-cities.zip` asset on the **published prerelease** tag `places-20261112-v2`. At review time this asset was present in the repository's releases (approximately 69 MB). Repository visibility also controls release-asset visibility.
- [ ] If the dataset is moved to a restricted channel, update `scripts/places/fetch_catalog.py`, packaging docs, and any download scripts **before** publicizing source.
- [ ] Verify the database license and rights of the underlying purchased source material; access via a GitHub Release is not authorization for general redistribution.
- [ ] Inspect all tags, historical releases, other attached files and any published compiled bundles.

## Source and history audit

- [ ] Search the **entire commit and PR history**, not just the HEAD tree, for credentials, private keys, API endpoints, personal data, private source, proprietary content, and any confidential URLs. Remove sensitive artifacts and rotate exposed secrets according to an approved incident procedure.
- [ ] Review all committed code/docs/tests/scripts for references to non-public resources; current optional private-artwork tooling and historical documentation must be explicitly approved for public disclosure or moved out of the public repository.
- [ ] Check dependency licenses of all npm and Cargo packages, fonts, icon packs and code snippets; add required third-party notices.
- [ ] Verify that only approved synthetic assets are generated by the default build and that all non-synthetic asset and location overlays remain excluded.
- [ ] Check configuration files, lockfiles, compiled/native artifacts, package manifests and `.gitignore` for accidental publishing.

## Documentation and build validation

- [ ] Confirm README contains **no link to a private repository** and every clone/build instruction works on a clean machine without private credentials.
- [ ] Test `npm ci`, `npm test`, `npm run build:ui` and relevant Rust/Tauri commands from a clean public-only checkout on Windows.
- [ ] Verify CPAL Exhibit B launch/session attribution appears in a real WebView2 application and links/URLs are not misleading; review responsive layouts.
- [ ] Verify LICENSE/NOTICE, security reporting, contributor guidance, current state, and test output.
- [ ] Verify no production account, real birth record, cloud sync, precise astronomy or signed installer is falsely advertised as implemented.

## Approval

- [ ] The maintainer explicitly approves making **source code** public, independently of approval to distribute binaries/data.
- [ ] Only after completing the above, change GitHub visibility manually and confirm a logged-out visitor can access the code, README and license but cannot obtain restricted private datasets.

No GitHub Actions or automated release is required or authorized by this checklist.
